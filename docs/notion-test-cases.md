# Тест-кейс із Notion → автотест

Вхід користувача: `Хочу покрити кейс TC-MP-005 по сторінці mainPage`. Достатньо назви сторінки й номера кейса. Номер `5` дозволено зіставити з суфіксом `005` лише за єдиного збігу в таблиці цієї сторінки; перед реалізацією завжди зафіксуйте повний ID.

## Доступ і джерела

Працюйте виключно через підключений **плагін Notion**. Окремий Notion MCP server, прямий REST/curl/SDK, браузер і читання токенів не використовуються. Внутрішній префікс інструмента `mcp__codex_apps__notion_*` допустимий лише коли його опис прямо вказує належність до плагіна Notion; це не дозвіл підключати окремий MCP. Якщо плагін недоступний — `NOTION_ACCESS_BLOCKED`, без альтернативного підключення.

Корінь: [QAuto — База знань](https://app.notion.com/p/3e06e1043eb281c1b4f9f501a1c6e1cb). Перед пошуком перевірте доступні інструменти плагіна; для поточного підключення `fetch self` показує доступ, а звичайний `search` доступний без AI search. Не вимагайте платного AI search, якщо завдання можна виконати через `fetch` і `search`.

- [Тест-кейси](https://app.notion.com/p/3e06e1043eb281d6998defa8f9bae8a5) — основне джерело сценарію.
- [Вимоги](https://app.notion.com/p/3e06e1043eb281ce95a5d85497c6ba6f) — уточнення **лише для вказаної користувачем сторінки**.
- [Сутності](https://app.notion.com/p/0b6e82daf9a54b33bcb9fa21c6958a74) та [API-операції](https://app.notion.com/p/0d8c299da87c4bf7905146b3536d32ac) — за потреби, лише записи, пов'язані з кейсом. Читання API-документації не означає виконання API-запитів.

## Analyzer: пошук до CLI та diff

1. Отримайте назву сторінки та номер кейса. Якщо одного немає — запросіть лише відсутнє значення. Відкрийте `Тест-кейси → <назва сторінки>` і знайдіть точний повний ID або єдиний збіг номера. Звірте ancestry з коренем QAuto.
2. Прочитайте повний рядок: ID, назву, передумови, кроки, очікуваний результат, ID вимог, статус. Порожня пошукова видача сама по собі не доводить відсутність: перевірте повну таблицю, доступні вкладені таблиці та пагінацію. Якщо відповідь обрізана або є непрочитані блоки — `NOTION_READ_BLOCKED`, а не `CASE_NOT_FOUND`.
3. Немає точного кейса в цій сторінці — `CASE_NOT_FOUND`: повідомте назву сторінки, введений номер і перевірене посилання, зупиніться без CLI, diff і записів у Notion. Кілька збігів — `CASE_AMBIGUOUS` та уточнення. Не створюйте відсутній кейс і не підміняйте його іншим джерелом.
4. Якщо кейс знайдено й потрібне уточнення, відкрийте **тільки однойменну сторінку** у `Вимоги`, насамперед зазначені в кейсі REQ-ID. Навіть якщо крок веде на іншу сторінку UI, її вимоги автоматично не читаються. Сутності й API читайте адресно для даних цього кейса. Суперечність, застарілий кейс або недостатній expected result — `CASE_SPEC_BLOCKED`; не обирайте довільне очікування.
5. Передайте повний кейс, URL/ID його Notion-сторінки, повний case ID, час читання, ID вимог і використані фрагменти джерел. Окремо зафіксуйте поточну комірку `Автоматизовано`.
6. Лише після успішного пошуку виконайте preflight та Playwright CLI, збережіть diff у `generated/diffs/` і покажіть для `APPROVE DIFF vN`. Назва тесту містить повний ID: `test('TC-MP-005 — <поведінка>', ...)`. Для handoff і Notion фіксуйте `tests/<файл>.spec.ts :: <точна назва test()>`.

## Координатор: колонка «Автоматизовано»

Поточні чотири сторінки містять **звичайні таблиці**, не Notion databases. У кожній додано одну rich-text колонку `Автоматизовано`; `☐`/`☑` — текстові позначки, не інтерактивний checkbox. Галочка й назва тесту містяться в одній комірці. Міграція таблиць у databases не потрібна.

| Подія | Значення для цільового кейса |
|---|---|
| Початкове налаштування без доказів автоматизації | `☐ Не підтверджено` |
| Аналіз / очікування APPROVE DIFF | Залишити поточне значення |
| Погоджений diff передано Implementer | `☐ В роботі — <файл> :: <назва тесту>` |
| Reviewer: CHANGES REQUESTED | `☐ Потребує виправлення — <файл> :: <назва тесту>` |
| Reviewer: VALID і фактичний успішний запуск поточного коду | `☑ <файл> :: <назва тесту>` |
| BLOCKED або BLOCKED_AFTER_2_RUNS після початку реалізації | `☐ <статус> — <файл> :: <назва тесту>` |
| Кейса немає / неоднозначність / блокування до реалізації | Не змінювати таблицю |

Після завершення кожного етапу координатор синхронізує тільки цю комірку. Analyzer і Reviewer читають Notion; Implementer повертає фактичні файли, точну назву тесту й evidence. Статус кейса `Актуальний`, його кроки, очікування та сусідні рядки не змінюються. `VALID` потребує покриття всього вибраного кейса; сам факт створення файла або часткового passing-тесту не дозволяє поставити галочку.

Перед записом повторно прочитайте цільову сторінку, знайдіть **рівно один рядок за повним case ID** й порівняйте його зміст із handoff. Змінився сценарій — `CASE_CHANGED`, поверніть Analyzer для нового diff/погодження; поточну автоматизацію не підтверджуйте. Не перезаписуйте паралельну зміну іншої назви тесту: повідомте `NOTION_SYNC_CONFLICT`.

Порівнюйте також поточну комірку з останнім підтвердженим значенням у handoff: будь-яку чужу зміну, навіть для тієї самої назви тесту, спочатку узгодьте. Зміна лише власного статусу автоматизації не є зміною сценарію. Якщо колонки немає або формат таблиці змінився, поверніть `NOTION_SYNC_BLOCKED` з описом схеми; не переписуйте таблицю за старим знімком.

Використовуйте плагінові `fetch` та `update_page` з `command: update_content`: точне зіставлення одного повного рядка (включно з case ID), заміна лише комірки `Автоматизовано`. Перед першою зміною контенту прочитайте `notion://docs/enhanced-markdown-spec` через `fetch` плагіна. Запропоновану зміну збережіть окремим diff у `generated/diffs/<завдання>-notion-vN.diff` з URL і case ID у handoff. Після запису повторно прочитайте рядок і звірте значення та решту комірок.

За помилки/невизначеного результату запису спочатку перевірте фактичний стан; не повторюйте запис наосліп. Якщо синхронізацію не підтверджено — повідомте `NOTION_SYNC_BLOCKED` окремо від вердикту тесту та збережіть очікуване значення для продовження. Не запускайте тест утретє заради синхронізації. У фінальній відповіді наведіть case ID, вердикт, кількість запусків і підтверджений стан Notion або blocker.

Оновлення колонки в межах цього флоу вже дозволене користувачем; окремого погодження на кожен запис немає. Ліміт тестових запусків залишається 2, кожен із `--retries=0`. Лічильник передається між ролями та не скидається зі зміною версії diff або повторним погодженням у межах того самого завдання.
