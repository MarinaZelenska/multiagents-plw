# Межі роботи AI-агента

Це навчальний Playwright-проєкт. Агент допомагає створити або перевірити один тест, але не є джерелом вимог і не може оголошувати запуск успішним без фактичного output.

## Робочий процес

1. Користувач називає сторінку та номер кейса. Analyzer через підключений плагін Notion знаходить рівно один кейс у `QAuto — База знань → Тест-кейси → <назва сторінки>`. Якщо кейса немає — `CASE_NOT_FOUND` і зупинка до CLI та diff. Для уточнення читає вимоги **лише вказаної сторінки**, за потреби — пов'язані сутності й API-операції. Далі виконує `npm run preflight`, сам досліджує UI через Playwright CLI, перевіряє локатори й одразу зберігає точний unified diff у `generated/diffs/<назва-завдання>-v1.diff`. Показує шлях, SHA-256, вміст diff, URL/ID кейса, джерела очікувань та CLI evidence. Тестові файли й Notion не змінює. Правила пошуку та синхронізації — `docs/notion-test-cases.md`.
2. Людина погоджує запропонований diff відповіддю `APPROVE DIFF vN`. Погодження стосується названого файла, його вмісту, вимоги й переліку цільових файлів.
3. Implementer перевіряє SHA-256 і вихідний стан, застосовує погоджений diff, виконує TypeScript-перевірку та перший запуск окремого Playwright Test із `--retries=0`. Він передає точні команди, exit codes і фактичний output.
4. Координатор одразу передає результат Reviewer. Reviewer звіряє spec, CLI evidence, diff, код і output. Якщо все валідно, він повертає `VALID` із доказами. Якщо ні — `CHANGES REQUESTED` із конкретними зауваженнями; координатор одразу повертає їх Implementer.
5. Implementer виправляє зауваження в межах погодженої вимоги й переліку файлів, зберігає кожен виправний diff окремим файлом `generated/diffs/<назва-завдання>-vN.diff`, виконує другий і останній запуск тесту з `--retries=0`, після чого Reviewer перевіряє знову. Для таких виправлень додаткове погодження людини не потрібне. Якщо змінюються вимога або перелік файлів, Analyzer готує новий diff для нового погодження.
6. Координатор через плагін Notion оновлює тільки колонку `Автоматизовано` цільового кейса за етапом реалізації/вердиктом: `☐` зі статусом і назвою тесту до успіху; `☑ <файл> :: <назва тесту>` лише після `VALID` і фактичного успішного запуску. Кожну зміну зберігає окремим diff у `generated/diffs/` та перевіряє повторним читанням. Після другого невдалого запуску записує `☐ BLOCKED_AFTER_2_RUNS` з назвою тесту й повідомляє користувачу. Якщо Notion не оновився — чесний `NOTION_SYNC_BLOCKED`, без додаткового тестового запуску.

Ліміт — **два запуски команди Playwright Test на одне завдання**: перший після застосування diff, другий після виправлення зауважень або діагностики failure. Кожен запуск має `--retries=0`, щоб налаштування retries у config не додавало прихованих спроб. Невдалий запуск, зокрема через середовище, теж зараховується. TypeScript, preflight, Playwright CLI, читання report/trace і статичне рев'ю ліміт не витрачають. Якщо після другого запуску Reviewer не може повернути `VALID`, автоматичний цикл зупиняється: координатор повідомляє користувача зі статусом `BLOCKED_AFTER_2_RUNS`, обома командами, exit codes, фактичними підсумками й невирішеною причиною. Третій запуск без нового завдання користувача заборонений.

Не перезаписувати попередні diff-файли. Застосовувати лише diff, який звірено з його SHA-256; не вносити непомічених змін. Дотримуватися `docs/test-standards.md` і передавати контекст за `templates/agent-handoff.md`. Позначати `FACT`, `ASSUMPTION`, `RISK`, `QUESTION` та `STOP` там, де це потрібно.

## Дозволено

- читати `README.md`, `pages/`, `tests/`, `labs/` і Playwright config;
- читати кейс і дозволені джерела Notion за `docs/notion-test-cases.md` виключно через підключений плагін Notion; окремий Notion MCP, прямий API та Browser connector для Notion заборонені;
- координатору після погодження diff оновлювати тільки комірку `Автоматизовано` знайденого кейса, включно з точною назвою тесту; окремого погодження цих статусних записів не потрібно;
- змінювати лише перелік файлів із погодженого diff або виправлення в тих самих межах; до погодження Analyzer може створити тільки новий файл запропонованого diff у `generated/diffs/`;
- використовувати `@playwright/test` і наявні залежності;
- запускати `npm run preflight`, окремий тест і читати локальні report/trace;
- Analyzer використовує Playwright CLI для пошуку й перевірки локаторів у
  поточному UI перед створенням diff тесту;
- для Playwright CLI одразу використовувати `.playwright/cli.config.json`;
  `playwright.config.ts` призначений для Playwright Test і не передається CLI;
  перший запуск робити як
  `npx playwright cli open https://qauto.forstudy.space --config=.playwright/cli.config.json`,
  без пробного запуску з іншим config;

## Потрібне підтвердження людини

- `APPROVE DIFF vN` перед застосуванням початкового diff; записати запропонований файл у `generated/diffs/` можна до погодження;
- зміна вимоги або переліку файлів — новий diff і нове погодження;
- додавання залежності, зміна config чи дія поза цим каталогом — лише за прямим завданням.

## Заборонено

- виводити в чат, terminal output або test evidence вміст `.env`,
  `.playwright/cli.config.json`, cookies чи tokens; CLI і Playwright Test можуть
  споживати локальний config без копіювання його вмісту до відповіді агента;
- змінювати baseline, config, package dependencies або product code без прямого завдання;
- використовувати непідтверджені CSS/XPath, fixed waits або вигаданий expected result;
- використовувати Browser connector для обов'язкової практики або просити
  людину вручну запускати Playwright CLI;
- виконувати commit, push, deploy або зовнішні write-дії, крім прямо дозволеного оновлення колонки `Автоматизовано` через плагін Notion;
- називати failure дефектом продукту до evidence-based діагностики.

## Definition of done

Page Object розташовані в кореневій `pages/` (`*.page.ts`), тестові сценарії —
у кореневій `tests/` (`*.spec.ts`). Не створювати `tests/pages/`.

Є збережений і погоджений початковий diff, перевірені джерела локаторів та
очікувань, фактичні файли й output окремого тесту або чесний blocker,
завершений цикл рев'ю та вердикт Reviewer `VALID`, `BLOCKED` або повідомлення
`BLOCKED_AFTER_2_RUNS` після вичерпання двох запусків.
Для Notion-кейса є повний case ID, посилання на джерело та підтверджене
оновлення `Автоматизовано` або явно повідомлений blocker синхронізації.

Якщо команда `npx --no-install playwright cli --version` недоступна або preflight показує
`Playwright CLI Chromium ready: false` чи `Playwright CLI config ready: false`,
поверніть `CLI SETUP BLOCKER` і точну інструкцію підготовки.
