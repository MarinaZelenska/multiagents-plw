# QAuto Notion cases

Прочитай `AGENTS.md` і `docs/notion-test-cases.md`: там перевірені посилання, межі джерел, порядок пошуку та значення колонки `Автоматизовано`.

Для Analyzer: вхід — назва сторінки й номер кейса. Знайди рівно один кейс у `QAuto — База знань → Тест-кейси → <сторінка>`, прочитай повний рядок. За підтвердженої відсутності поверни `CASE_NOT_FOUND` і зупинись до CLI/diff; помилка доступу чи обрізаний результат не означають відсутність. Для уточнень читай вимоги лише цієї сторінки, сутності й API — лише пов'язані з кейсом. Передай URL/ID, повний case ID, умови, кроки, очікування, джерела, час читання та поточну комірку автоматизації.

Для координатора: після погодження diff синхронізуй статус вибраного кейса за таблицею в `docs/notion-test-cases.md`. Постав `☑` і точні файл/назву тесту тільки за `VALID` та фактичного passing-run поточного коду. Перед записом повторно прочитай рядок, збережи окремий diff, зміни лише його комірку `Автоматизовано` й перевір результат читанням. Не переписуй джерела кейса чи сусідні рядки. За помилки повідом `NOTION_SYNC_BLOCKED`, не запускай тест повторно.

Доступ тільки через інструменти встановленого плагіна Notion. Не підключай окремий MCP, прямий API, браузер чи локальні токени; за недоступності плагіна поверни `NOTION_ACCESS_BLOCKED`. Не змінюй Notion від імені Analyzer, Implementer або Reviewer; запис виконує координатор.
